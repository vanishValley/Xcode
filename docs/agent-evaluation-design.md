# Agent 评测模块设计

评测模块固定任务、初始代码、运行配置和验收条件，用于比较 Agent 在完成质量、重复运行稳定性与资源消耗上的表现。

## 执行流程

```text
加载 Task 与运行配置
  → 创建独立工作目录，写入初始源码
  → 新 JVM 运行现有 Agent
  → 通过统一 Trace 采集调用、用量和故障
  → 正常结束、预算耗尽或超时停止
  → 独立目录重新编译候选源码
  → 行为测试、回归测试、修改约束检查
  → 逐次结果、分类汇总与配对对照
```

Agent 工作区的旧 class 文件、修改后的测试和自述结果不参与最终评分。裁判复制允许修改的源码、恢复受保护文件并加入隐藏检查，再通过 `javac` 和 `java -ea` 验收。

## 模块职责

| 组件 | 职责 |
| --- | --- |
| `EvalTask` | 题意、文件快照、参考解、可修改范围和验收契约 |
| `EvalRunner` / `EvalProcess` | 工作目录、子进程、超时、停止与逐次产物 |
| `EvalAgentMain` | 装配现有 Agent、统一观测、请求预算与工具故障注入 |
| `EvalGrader` | 编译、行为、回归和约束检查 |
| `EvalReport` | 分类汇总、重复尝试与同条件配对比较 |
| `EvalMain` | 命令入口、配置和运行元数据 |

模型调用与工具记录复用可观测模块。评测预算装饰器只控制准入；用量和报告读取 `ExecutionSnapshot`，避免再维护独立的模型记账或工具日志。

## 题库与配置

Java v1 包含 20 道任务、16 个问题家族：8 道缺陷修复、4 道功能开发、4 道重构、2 道故障恢复和 2 道约束任务。15 道 dev、5 道 holdout 按问题家族划分，同源变体不跨集合。答案保存在仓库中，holdout 是开发流程约定。

| Profile | 执行配置 |
| --- | --- |
| `no-goal` | ReAct，不额外设置目标锚点 |
| `react` | ReAct，设置任务目标 |
| `review` | ReAct 后审查，不通过时最多反馈修复一次 |
| `plan` | 现有 Plan-and-Execute |
| `team` | 现有 TeamCoordinator |

真实对照固定模型、题目和外层预算，并保留各模式内部调度约束。`no-goal` 与 `react` 用于比较目标注入；其他模式比较完整执行配置。脚本化链路检查仅支持 `react` / `no-goal`。

## 指标与验收

- **质量：**通过率、分类通过率及编译、行为、回归、约束检查结果。
- **稳定性：**同题多次尝试的至少一次成功比例与全部成功比例；不完整重复组单独展示。
- **效率：**执行耗时 p50/p95、已知输入/输出 token、模型及工具请求次数，失败尝试也参与统计。
- **证据完整性：**缺少模型 usage、子进程异常或超时均保留不完整标记，已知 token 不代表完整费用。

任务通过要求运行正常结束并满足全部外部验收。故障恢复题还要求注入确实触发。执行错误、超时和预算耗尽计入失败；环境无法准备或裁判无法执行时分类为基础设施错误。

参考解必须通过，初始缺陷必须被验收发现，同时初始版本的可见回归检查应通过。该双向校验用于检查题目与裁判本身。

## 隔离与预算

每次尝试使用新 JVM 和新工作目录，避免普通会话及工作区状态串题。任务集顺序执行，减少本机资源竞争。模型请求数通过配额控制，token 按已知 usage 在下一次请求前检查；在途请求可能使最终用量超过阈值。

当前没有操作系统级沙箱，不自动加载用户全局记忆、Skills 和外部 MCP。两道恢复题只注入执行前的确定性读写失败，不代表任意副作用错误都能安全重试。

运行元数据包括配置、JDK、操作系统、题目哈希和打包 JAR 指纹。逐次结果关联工作区、独立验收目录和 Trace 索引。详见 [Benchmark 使用说明](../benchmarks/java-v1/README.md) 与 [统一观测设计](observability-evaluation-design.md)。
