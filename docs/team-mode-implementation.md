# Team 协作设计与使用

Team 模式在单 JVM 内运行主 Agent 与独立成员，支持动态委派、消息与任务续接。当前成员只读，修改由主 Agent 集中执行；尚未支持成员互发消息、递归委派或崩溃后自动续跑。

## 使用

按 README 的方式编译并启动应用，在 TUI 或 plain 模式中输入：

```text
/team 从前端请求和后端配置两个方向调查跨域登录失败，汇总证据后修复并验证
```

一次 `/team` 创建一个临时团队。主 Agent 可以决定不派发小任务，也可以动态创建、通知、继续和停止成员。命令结束后结果以普通对话消息回灌，下一条普通输入不会自动保持 Team 模式。

子 Agent 只使用读取、搜索、Skill 加载和汇报工具；不提供通用 Shell、写文件和未分类 MCP。主 Agent 只有在没有成员处于创建、排队、运行或取消中状态时，才能取得工作区独占租约执行可变操作。不是把 Shell “约定为只读”。

## 代码入口

| 文件 | 职责 |
| --- | --- |
| `com.xu.team.TeamCoordinator` | 团队装配、总超时监控、收尾、报告 |
| `com.xu.team.TeamRuntime` | 状态机、异步创建、消息、续接、问题、等待与工作区阶段 |
| `com.xu.team.TeamToolRegistry` | 主/子角色工具视图、调用身份、路径限制、保留审批链 |
| `com.xu.team.TeamModelClient` / `TeamBudget` | 共享真实模型客户端，预算预留和结算，包括压缩请求 |
| `com.xu.team.TeamEventStore` | 单写入者保存事件、结果和团队清单 |
| `com.xu.agent.AgentRunHooks` | 请求边界消息输入、暂停、候选最终答案检查 |
| `MemoryManager.forTeam` | 独立压缩、公共记忆检索，不写普通会话或自动提炼长期记忆 |
| `CommandProcessor` / `Main` | `/team` 路由与装配，已有普通与 Plan 路径保留 |

Java 17 的有界 ThreadPoolExecutor 负责执行成员，主 Agent 不占成员线程池。每个成员只允许一个执行者，任务结束后保留 Agent 对象和历史。每轮重置该成员的取消 generation，且与 stop 在同一状态锁下协调；已失败或已取消成员不会被自动续跑。

## 消息语义

- `NOTIFY`：补充当前调查，在下一次请求边界进入历史；成员空闲时只入队。
- `CONTINUE`：下一轮任务，复用成员上下文；运行中只排队，不并发调用该成员。
- `ANSWER`：必须关联有效 questionId；即使回答早于暂停结算到达，也会在下一轮正确处理。
- `report_to_parent` 的 `QUESTION + needsReply=true`：补全当前工具批次的协议结果，再暂停，不把它当作执行异常回滚。
- `resolve_question`：记录明确取消或不适用原因。不会伪造用户批准。

通知和续接分别使用有界队列，每类默认 32 条；ANSWER 保留控制容量，防止消费者因为队列满而无法被唤醒。状态与邮箱在短锁下修改，模型、工具和磁盘 I/O 不在状态锁内执行。

主 Agent 在请求边界自动接收事件，`wait_agents` 用于等待下一批更新；两条入口共用已消费位置。afterSequence 只接受已返回的游标，不能用自造游标跳过未读结果。事件投递/进入历史/请求尝试不等于模型已经理解或完成工作。

`get_agent_result` 可以按 offset 读取完整结果，事件只携带摘要与引用。`list_agents` 包含当前问题和最新 resultId；这些信息由运行时保存，不依赖历史压缩是否保留了具体 ID。

## 配置

以下 JVM 属性在创建团队时读取：

| 属性 | 默认值 | 含义 |
| --- | --- | --- |
| `xcode.team.maxCalls` | 100 | 全团队模型调用上限，包括上下文压缩 |
| `xcode.team.maxTokens` | 500000 | 团队估算与结算 token 预算 |
| `xcode.team.outputTokens` | 4096 | 每次请求输出上限，发送为 max_tokens |
| `xcode.team.timeoutSeconds` | 900 | 团队截止时间 |

例如 JVM 参数放在 `-jar` 之前：

```text
java -Dxcode.team.maxCalls=60 -Dxcode.team.timeoutSeconds=600 -jar target/Xcode-1.0-SNAPSHOT.jar
```

其他上限在 TeamConfig 的类型配置中集中设置：四个并行成员、八个存活成员、十二次累计创建尝试、有界线程池队列。失败的创建也计入尝试次数；同一个工具调用的重试通过 operationKey 返回原成员，不重复创建。

输入估算包含序列化历史和工具定义，并采用保守估值；实际 usage 用于结算，缺失用量的失败请求保留预估成本。因此这不是服务商计费级的绝对费用上限，也不是性能收益数据。未知模型用量和估算误差需在报告中考虑。

## 取消与最终结果

单成员取消中断自己的执行线程和取消作用域，不调用共享客户端的全局取消去误伤兄弟成员。团队总取消/超时由监控器传播。只有执行函数实际退出才标记 CANCELLED；退出超时会标记 unsafe 并阻止复用运行环境。

主 Agent 的纯文本回答先经过完成检查：活跃成员、未解决问题、未读关键结果和未消费通知都会阻止提前结束。检查与团队关闭在同一锁下完成。模型耗尽轮次时输出部分报告并回收成员，不宣称成功。

这个关口验证运行时状态，不会自动证明业务结论正确。主 Agent 仍需要真实工具证据和集成验证，模型自述“测试通过”不能替代工具退出结果。

## 记录与限制

记录位于 XcodePaths 的项目数据目录下 `teams/<teamId>/`，包含 manifest.json、events.jsonl 和 results。manifest 中有目标、最终状态、成员状态和用量。日志复用脱敏；请求追踪记录运行 ID、请求 ID 和文本中出现的消息引用，供排查，不把引用出现当作可靠的业务处理确认。

记录采用有界异步写入，进程崩溃可能损失尚未刷盘内容。第一版没有 transcript 恢复协议，也不会自动把旧 ACTIVE 团队重新启动。异常退出留下的清单只能作为现场线索，需检查工作区后重新发起任务。日志失败会停止接收新工作，报告记录不完整。

工作区 epoch 仅反映本团队主 Agent 管理的可变操作，不检测外部编辑器或其他进程的修改。根目录 AGENTS.md 在启动时读取并供本团队使用；未实现完整祖先/嵌套规则发现。公共规则文件过大时不自动注入，可在任务中要求主 Agent 读取相关部分。

成员类型、工具视图和结果存储按职责组织。团队部分结果与普通会话回灌已实现，崩溃续跑、子 Agent 编辑和自动评估真实模型收益保留为后续工作。

## 验证

运行 `mvn test` 执行现有回归测试和 Team 测试。新增测试使用可控假模型、CountDownLatch 与有界事件等待，不需要 API Key。

覆盖动态创建、重复调用去重、串行续接、提前回答、队列背压、取消创建和排队任务、未退出状态、候选完成检查、工具批次暂停配对、读写权限、工作区独占、独立记忆压缩、模型预算、记录保存以及 `/team` 端到端路由。

假模型验证的是运行时协议与接入正确性。尚未进行在线真实模型的质量、耗时和费用对比，不据此给出成功率提升或 token 节省百分比。
